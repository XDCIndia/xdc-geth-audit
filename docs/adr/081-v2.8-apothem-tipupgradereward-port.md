# ADR 081 — Port XDPoSChain v2.8.0 apothem upgrade (TIPUpgradeReward tier rewards + co-forks)

- Status: IN PROGRESS (staged; activation deferred)
- Issue: XDCIndia/go-ethereum#963
- Branch: `feat/963-v2.8-apothem-config`
- Date: 2026-06-18

## Context

XDPoSChain `release/v2.8-testnet` (PR #2383, merged 2026-06-18) activates **four co-forks
on apothem at block 83,600,000**: `PragueBlock`, `DynamicGasLimitBlock`,
`TIPUpgradeRewardBlock`, `TIPUpgradePenaltyBlock`; plus a new V2 masternode tier at
**round 27,360,000** (`MaxMasternodes 25` + `MaxProtectorNodes 3` + `MaxObverserNodes 2`;
rewards 63.42 / 50.27 / 25.13 XDC; `MinimumSigningTx 30`). Apothem was at ~83.24M when this
was written, so block 83.6M is ~8 days out. Our modern fork (v1.17.3 base) had none of it.

All four forks co-activate; **none can be enabled alone** — Prague-only at 83.6M (without
the reward/gas/penalty changes) still diverges from canonical. No apothem value flips to
83.6M until all behaviors are ported AND parity-tested together on the gp5-113 private V2 net.

## Decision — #186/#188 reconciliation (the consensus-critical one)

`RewardVoterPercent == 0` on all XDC networks, so in `GetRewardBalancesRate`
`balances[foundationWalletAddr]` is always nil before the foundation line **unless
`owner == foundation`**. Our two XDC-only deviations (the #186 owner-skip and the #188
unconditional foundation accumulate) are therefore **net-equivalent to canonical v2.6.8 for
every pre-fork apothem block** — the owner-skip is a faithful re-expression of canonical's
last-write-wins-on-foundation. Conclusion:

> **Do NOT touch the validated pre-fork reward path (`consensus/XDPoS/reward.go`).**
> Route the post-fork tiered reward through a SEPARATE, fork-gated path that mirrors
> canonical v2.8 exactly (no owner-skip; foundation accumulate gated on IsTIPUpgradeReward).

Because the apothem fork block ships `nil` (disabled) until canary-validated, the entire
post-fork branch is dead code in production at merge time — zero live-behavior regression.

## Other decisions

- **Per-network gate**: replace the disabled global `common.TIPUpgradeReward = 9999999999`
  with per-chain `ChainConfig.TIPUpgradeRewardBlock` / `TIPUpgradePenaltyBlock`
  (matches v2.8). nil ⇒ disabled ⇒ behavior-identical to today. Apothem left nil for now.
- **Prague**: add block-based `PragueBlock` + `IsPragueBlock(num)`, wired into the XDC branch
  of `Rules()`, mirroring the existing `CancunBlock`/`IsCancunBlock` precedent. (Timestamp-
  derived `PragueTime` rejected — block/time drift = consensus-fork risk.)
- **DynamicGasLimit**: our miner already hones via `core.CalcGasLimit` toward `xdcGasCeil`
  (420M). Whether this fork is a no-op or a 420M→42M transition depends on the operator
  `--miner.gaslimit` canonical apothem v2.8.0 masternodes will run — **HELD pending chain-team
  confirmation** (a 42M target risks the #952 halt mode).
- **MintedRecord**: post-fork path writes cumulative minted/burned per epoch into the
  `0x…009a` SMC; the typed wrappers were absent and an incompatible dead local layout
  (slot-1 collision) existed → removed and replaced with the bit-for-bit v2.8 layout.

## Staging

- **A — state plumbing** (this commit): `common.Uint64ToHash`, `common.ExtractAddressFromBytes`,
  MintedRecord wrappers (+ delete dead colliding funcs). Zero behavior change.
- **B — config plumbing**: per-network fork fields + repointed gates + `IsPragueBlock` + Rules
  wiring + `ApothemV2Configs[27360000]` tier entry. All apothem fork values DISABLED.
- **C — reward logic**: `Beneficiary` enum, `CalculateRewardForSignerFixed`, tiered
  `GetSigningTxCount`, `GetRewardBalancesRateUpgrade` (no owner-skip), the gated HookReward
  branch + MintedRecord bookkeeping. Dead code until activation.
- **D — validation + activation**: parity-harness across the 83.6M boundary + ≥3 post-fork
  epoch boundaries vs a canonical XDPoSChain v2.8 node; resolve the gas-ceiling question;
  only then flip apothem `TIPUpgradeRewardBlock`/etc. to `83600000`.

## Must verify empirically before activation (risk register R1–R7, see #963)

R1 round-27.36M active at block-83.6M + active-set 108→25; R2 `big.Float` reward truncation
golden vs canonical; R3 MintedRecord slot/key bit-parity; R4 post-fork never routes through
the owner-skip path; R6 penalty-decode parity; R7 stable-sort tie-break determinism.
